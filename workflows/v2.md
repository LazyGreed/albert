# Workflow v2

Use one dependency DAG for two or more implementation streams or when a
verified stream changes. Reject cycles across hard and read-only edges;
give each path one writer.

**Worker brief (Felix and Vera).** Put `WORKFLOW: v2`, `STREAM`, and
`CHECKOUT` (native worktree and branch) on one line. Add `GOAL`,
`WRITE OWNERSHIP`, `DO NOT EDIT`, and `ACCEPT` (focused runnable command and
expected result, or observable outcome and evidence gap if no command can
run). Add `DEPENDENCIES` for hard prerequisites and `READS` for narrow read
paths outside ownership; name each provider. Include needed input bindings.
Omit `INSTANCE/ROLE`, `VERIFIER`, empty fields, and ref history.

## Gate inputs

The coordinator owns the complete plan (including pending streams) and
its change record. Keep plan and evidence outside worker checkouts and
bound Git state stable through checks and landing. Harvest checkout refs
and give Vera pre-filled bindings plus check evidence (checkout/ref, command,
exit status, output). Vera confirms revisions reviewed and checks observed,
then issues an independent verdict. Workers do not reconstruct the ledger.
The checker verifies Git consistency, not provenance. Never guess a binding
or substitute current `HEAD` for the ref actually reviewed or tested.

Use blank-line-separated `key: value` records. In the plan, use one `id` per
stream and repeat `write` and `read` for path patterns (`check-ownership.sh`
globs). Use `depends` for hard upstream IDs and `read_depends` for read-only
upstream IDs. Declare an edge for every read of another stream's owned path;
each read-only edge needs a `read` pattern.

For each observed stream, record `id`, `ref`, and `worktree` from the checkout
and copy `status`, `verdict_ref`, `verdict_base`, and `verified_against` from
Vera's verdict separately. Verdicts bind `REF` as `branch@sha`, `BASE` as a
bare target SHA, and `VERIFIED_AGAINST` as one `ID=BRANCH@SHA` per direct
upstream (repeat `verified_against` in evidence). With no upstreams, Vera
reports `VERIFIED_AGAINST none`; omit `verified_against` in evidence. Use
`--base-ref "$target_branch@$BASE"` for the current local target. The checker
resolves abbreviated SHAs and compares branch names exactly. Exit codes:
0 pass, 1 failed gate, 2 malformed input.

## Gates

**All-root batch.** Use one edgeless plan. With an empty evidence file, run
`ready` once without `--stream`. Skip combined trials for independent peers.
Once all streams have a current `PASS`, run `invalidate` once without
`--stream` immediately before landing. Ownership, review, and join still apply.

1. **Ready.** Run `check-graph.sh ready --plan "$plan" --base-ref "$base_ref" --stream "$id" "$evidence"`.
   Use `--repo` for an external base lookup without prerequisite checkouts.
   An empty evidence file suffices for a root. Ready checks the full plan and
   requires current independent `PASS` and committed ownership for the
   selected stream's transitive prerequisites. Omit `--stream` to check every
   entry. Confirm isolated worktrees before dispatch. Serialize read/write
   overlap unless a speculative reader's brief binds a frozen, clean upstream
   `PASS` and the writer works elsewhere. Record the frozen input; re-verify
   the reader independently after the writer's new `PASS`, even if reads
   are unaffected.
2. **Invalidate.** Run `check-graph.sh invalidate --plan "$plan" --base-ref "$base_ref" --stream "$id" "$evidence"`
   before landing unless a current whole-plan pass covers the stream. Reuse
   that pass only while the plan, stream evidence, and bound Git state are
   unchanged. The gate checks the stream and all its upstreams; omit
   `--stream` to check all planned streams. Branch and HEAD
   must match the observed ref and Vera's `REF`; her `BASE` must resolve to
   the target tip. `check-ownership.sh` checks the net patch and each commit's
   parent diff against declared writes. Start at the target base, separate
   from upstream work. Keep the range above `BASE` linear and its net patch
   nonempty. Check dependents in clean trials combining stream and intended
   upstream refs. Replay the stream if it no longer descends from the target.

   Hard bindings must match current verified upstream refs exactly. On a
   read-only edge, keep the exact ref Vera checked. If upstream moved, the
   old commit must remain in its ancestry at or above `BASE`; compare the
   diff to `READS`, including both paths of renames and copies. Keep the
   verdict only if the paths are disjoint. A stale upstream blocks its
   dependents; once it regains `PASS`, retain downstream evidence if its
   verified ref and other inputs are still current. When a binding or gate
   failure makes a prior `PASS` stale, use that failure to `baseline` or
   `reopen` the stream and reserve an attempt with `begin` before the first
   recovery re-verification, including a clean no-edit trial. Re-verify stale
   streams in clean trials before rerunning Felix. If one change invalidates
   more than three streams, run one contract or integration check, or pause
   for confirmation. This does not waive evidence requirements.
3. **Join.** Build a dedicated integration branch and worktree from the current
   target and verified stream commits. Require a current whole-plan
   `invalidate` pass before recording the combined result. Run combined
   checks at `INTEGRATION_REF` (branch and HEAD) in the clean integration
   worktree. Separately record observed `status`, tested `integration_ref`,
   `verdict_base` (`BASE`), and each tested `INPUT_REFS` entry as
   `input_ref: ID=BRANCH@SHA` (one per planned stream).
   Run `check-graph.sh join --plan "$plan" --base-ref "$base_ref" --integration-ref "$INTEGRATION_REF" --integration-worktree "$integration_worktree" "$evidence"`.
   Join rechecks the graph and stream evidence, requires a combined `PASS`
   bound to the current integration ref, base, and complete input list, and
   checks that the base and inputs are ancestors of integration HEAD. The
   final tree and each integration merge must contain exactly the patches of
   reviewed tips in its ancestry. Merge parents must be the target base, a
   complete reviewed stream tip, or a checked integration merge. Route fixes
   to the owner or add a disjoint, reviewed integration-fix stream to the
   plan. When a binding or gate failure makes a prior combined result stale,
   use that failure to `baseline` or `reopen` `integration`. Reserve an attempt
   with `begin` before the first combined recovery recheck, including a no-edit
   recheck. Rerun join before final merge.

Bound worktrees must be full, clean checkouts in one Git common directory.
The gates use `check-ownership.sh` to reject staged or unstaged changes,
non-ignored untracked paths, populated or unreadable submodule paths,
assume-unchanged and skip-worktree entries. They read only Git, plan, and
evidence. Set `TMPDIR` outside Git repositories for checker scratch files.

## Recovery

The coordinator records one durable ledger path with the task plan, outside
worker checkouts. Use `scripts/check-recovery.py --help` in the selected
verification skill (`skills/verification/scripts/check-recovery.py` in the
Quintet source). Follow the skill's recovery guide. Initialize once to pin
the per-scope limit (default eight).

Baseline each stable scope before retrying. Keep its original ID through
renames and re-creation. Charge routed fixes to the owning stream and use
one shared `integration` scope for dedicated fixes and combined rechecks.
During recovery, reserve a numbered attempt with `begin` before a Felix
edit plus Vera re-review or a no-edit recheck. Record its result with
`finish`. Use `reopen` in the same scope when verification discovers a
subsequent failure after a pass. Compare failures in the new episode and
retain the scope's spent retries and history.

Compare failure counts within the same check set. After two unproductive
attempts, record Nora's finding and a changed tactic. When evidence invalidates
a plan assumption, record and verify the replan before retrying. When both
steps are pending, record the strategy before the replan. Pause for external
blockers and bind `unblock --block` to the current `block_sequence` after
observing user intervention. Stop at exhaustion or when, after a replan, a
failure fingerprint repeats within the current episode.
Report `BLOCKED` with failing checks, stale streams, refs, worktrees, and
the next action. Independent review and graph gates still apply.

On resume, reopen that ledger path with `status` and reconcile pending
attempts against Git, verdicts, and native sessions. Finish or abandon the
reserved attempt using its original number. Preserve abandoned worktrees
and branches, skip unstarted work, and keep the original scope IDs with the
task evidence.
