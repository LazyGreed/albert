# Workflow v2

Use one dependency DAG for two or more implementation streams or when a
verified stream changes. In Felix and Vera briefs, use `WORKFLOW: v2`,
`DEPENDENCIES` for hard prerequisites, and `READS` for narrow paths outside
write ownership. Name the provider for each read-only edge. Keep the graph
acyclic across both edge types and give each path one writer.

## Gate inputs

Keep the plan and evidence outside worker checkouts. The coordinator owns the
complete plan, including pending streams, paths, and edges. Record changes to
the plan explicitly. Populate the evidence file from observed checkouts, Vera's
independent stream verdicts, and the recorded combined check. The checker
validates the consistency of these inputs against Git. The coordinator is
responsible for their provenance and for holding the relevant refs and
worktrees stable during checks and landing.

The files contain blank-line-separated `key: value` records. In the plan, use
`id` once per stream. Repeat `write` and `read` for distinct path patterns. Use
`depends` for hard upstream IDs or `read_depends` for read-only upstream IDs.
Declare an edge wherever one stream reads a path another stream owns. A
read-only edge requires a `read` pattern. Paths use the same glob syntax as
`check-ownership.sh`.

In evidence, give each observed stream a record with `id`, `ref` and
`worktree` from its checkout. Copy the verdict's `status`, `verdict_ref`,
`verdict_base` and repeated `verified_against` entries independently from
Vera's record. In verdicts, use `branch@sha` for `REF`, a bare target commit
SHA for `BASE`, and `ID=BRANCH@SHA` for each direct input in
`VERIFIED_AGAINST`. Include exactly one entry per declared upstream. Streams
with no upstreams omit `verified_against`. Use `--base-ref "$target_branch@$BASE"`
for the current local target branch. The checker resolves abbreviated SHAs to
commits and compares branch names exactly. Malformed records produce exit 2.
A failed gate produces exit 1, and a passing gate produces exit 0.

## Gates

1. **Ready.** Run `check-graph.sh ready --plan "$plan" --base-ref "$base_ref" --stream "$id" "$evidence"`.
   Use `--repo` for a base lookup outside the current repository when there
   are no prerequisite checkouts. An empty evidence file is enough for a root
   stream. The gate checks the full plan and the selected stream's transitive
   prerequisites, including their independent current `PASS` records. Omit
   `--stream` to check prerequisites for every plan entry. Confirm isolated
   worktrees before dispatch. Serialize read/write overlap by default. A
   speculative reader may start with an explicit frozen, clean, bound upstream
   `PASS` in its brief if the writer works elsewhere. Record that frozen input
   and independently re-verify the speculative reader after the writer's new
   `PASS`, even if the diff leaves the reads untouched.
2. **Invalidate.** Run `check-graph.sh invalidate --plan "$plan" --base-ref "$base_ref" --stream "$id" "$evidence"`
   before landing each stream. The gate checks the selected stream and its
   upstream closure. Omit `--stream` to require all planned streams to pass.
   The stream's checked-out branch and HEAD must match the observation and
   Vera's `REF`. Vera's `BASE` must resolve to the current target tip. The
   checker runs `check-ownership.sh --base BASE --head HEAD --require-changes`
   with the stream's declared write patterns. Start each stream at the target
   base and keep its committed patch separate from upstream work. Stream ranges
   above `BASE` must be linear and contain a nonempty owned patch. Use a clean
   trial worktree combining the stream and intended upstream refs for dependent
   checks. Replay the stream patch from the current target if the old branch
   no longer has that base in its ancestry.

   Hard evidence must match each upstream's current verified ref. For an ordinary
   read-only edge, keep the exact ref Vera last checked. If it moved, the old
   commit must be in the current upstream's ancestry at or above `BASE`. The
   gate checks the diff between those commits against the declared reads,
   including both paths of a rename or copy. Retain the existing verdict if
   those paths are disjoint. A stale upstream verdict also blocks its
   dependents. Once Vera restores its `PASS`, downstream evidence remains usable
   when the verified ref and all other inputs are still current. Re-verify in a
   clean trial worktree before rerunning Felix. If one change invalidates more
   than three streams, run one contract or integration check, or pause for
   confirmation. The evidence requirements still apply.
3. **Join.** Build the integration worktree from the current target and the
   verified stream commits. Before recording the combined result, run
   `invalidate` for the whole plan. Confirm the clean integration worktree,
   capture its branch and HEAD as `INTEGRATION_REF`, and run the combined checks
   at that commit. Record their result separately in evidence with `status`,
   `integration_ref`, `verdict_base`, and one `input_ref: ID=BRANCH@SHA` per
   planned stream. Each value comes from the recorded combined check's inputs.
   Then run
   `check-graph.sh join --plan "$plan" --base-ref "$base_ref" --integration-ref "$INTEGRATION_REF" --integration-worktree "$integration_worktree" "$evidence"`.
   Join rechecks the graph and all stream evidence, requires a combined `PASS`
   bound to the current integration ref, base, and complete input list, and
   checks that the base and input commits are ancestors of integration HEAD.
   The integration tree must contain exactly the planned patches, and non-merge
   commits must come from those histories or the target base. Route fixes to
   the owning stream or update the plan for a disjoint integration fix with its
   own reviewed stream. Rerun the gate before final merge. An edit plus Vera
   re-review uses one of two global rounds. Stale rechecks alone use no round.
   At the cap, report failing checks, stale streams, refs, and worktree paths.

All bound worktrees must be clean and share one Git common directory. The
gates check tracked and untracked changes, force submodule visibility, and
reject assume-unchanged and skip-worktree entries, including in initialized
submodules. Use full checkouts for these gates. They only read Git, the plan,
and the evidence, and write scratch files outside the worktrees.

On resume, derive `pending`, `dispatched`, `reported`, `verified`, `stale`,
`abandoned`, or `landed` from Git, verdicts, and native sessions. Skip unstarted
work and preserve abandoned worktrees and branches. Record status in an
existing issue or PR when needed.
