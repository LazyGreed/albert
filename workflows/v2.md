# Workflow v2

Use one dependency DAG when there are two or more implementation streams or
when a verified stream changes. Edges point from provider or writer to
dependent or reader. Set `WORKFLOW: v2` in Felix and Vera briefs. Use
`DEPENDENCIES` for hard prerequisites and `READS` for narrow paths outside
write ownership. Record `REF` when Felix reports it. Bind Vera's verdict to
`REF`, `BASE`, and `VERIFIED_AGAINST`, including for single-stream reviews.
Use the bare target commit SHA for `BASE` in both `STREAM` and `JOIN` verdicts.
For `--base-ref` only, set `base_ref="${target_branch}@${BASE}"`.
At each gate use `check-graph.sh` from the verification skill with `$spec`
containing the stream records for that gate.

1. **Ready.** Run `check-graph.sh ready "$spec"` with planned ownership and
   reads. Resolve cycles across both edge types before dispatch. The check
   binds each hard dependency's `PASS` to its clean worktree. Confirm clean,
   isolated checkouts for concurrent writers.
   Serialize read/write overlap by default. A speculative start against an
   active writer requires an explicit, frozen, verified ref in the brief and
   re-verification after the writer's new `PASS`.
2. **Invalidate.** Before landing, run
   `check-graph.sh invalidate --base-ref "$base_ref" "$spec"`. Require a current
   local base tip, clean worktrees at their recorded refs, and each hard
   input's current `PASS` and exact `VERIFIED_AGAINST` evidence. For a read-only
   edge, supply the last checked upstream commit (the merge base on the first
   comparison). Retain that evidence only when the diff has no intersection
   with the reads. Speculative readers still need
   re-verification. Treat stale streams as unverified. Have Vera re-verify in
   a clean trial checkout combining the stream `REF` and all intended upstream
   commits before rerunning Felix. When edits are needed, re-verify Felix's
   updated `REF`. Keep downstream evidence when the downstream input `REF`
   stays unchanged and other inputs remain current. If one change invalidates
   more than three streams, run one contract or integration check, or pause
   for confirmation. The evidence requirements still apply.
3. **Join.** Run `check-graph.sh join --base-ref "$base_ref" --integration-ref "$INTEGRATION_REF" --integration-worktree "$integration_worktree" "$spec"`
   with all `INPUT_REFS` in the spec. Run the separate combined check at the
   bound integration commit. Rerun the gate before final merge using the
   recorded bindings. Any movement makes the check stale. Route
   failures to the owning Felix or serialize an integration Felix with
   temporary ownership of the affected paths. An edit plus Vera re-review
   uses one of two global rounds. Stale rechecks alone use no round. At the
   cap, report failing checks, stale streams, refs, and worktree paths.

On resume, derive `pending`, `dispatched`, `reported`, `verified`, `stale`,
`abandoned`, or `landed` from Git, verdicts, and native sessions. Skip unstarted
work and preserve abandoned worktrees and branches. Record status in an
existing issue or PR when needed. Keep status files out of worker checkouts.
